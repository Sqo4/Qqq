# 🐝 Улей

Распределённая нейросеть на видеокартах добровольцев. **Одна большая языковая модель** (по умолчанию Qwen3 32B) делится на части, и каждая часть живёт на видеокарте одного из участников. Вместе они работают как одна модель, которая не поместилась бы ни на одну игровую видеокарту.

Поверх модели работает сервис для людей:
- у каждого свои **личные чаты** с нейросетью;
- есть **общий чат**, куда можно делиться проектами;
- есть **проекты**: группа (например, 5 студентов) переписывается в общем чате проекта и зовёт нейросеть через `@улей`;
- **табло мощностей в прямом эфире** показывает, сколько всего мощности, сколько занято, сколько компьютеров онлайн и в каком состоянии цепочка.

```
 браузер (чаты, проекты, табло) ─HTTPS/SSE─► координатор ──► голова llama-server
                                                  │                  │ слои модели
                                    туннель ◄─────┘                  ▼
 компьютер участника ── rpc-server (127.0.0.1) ◄── соединение открывает сам участник
```

Компьютеры участников сидят за домашними роутерами, поэтому каждый из них сам открывает защищённое соединение к серверу. Сервер ходит к видеокарте только по нему. `rpc-server` слушает только `127.0.0.1`, снаружи к нему не подключиться. Если участник запускает игру, его часть освобождается, и сервер пересобирает цепочку из запасных участников.

Есть и второй режим, «маленькие модели»: каждый узел целиком считает небольшую модель (как AI Horde). Он включается флагом `-model qwen3-4b`.

## Из чего состоит

| Папка | Что это |
|---|---|
| `coordinator/chain.go` | Сборщик цепочки: выбирает участников, чья видеопамять покрывает модель, запускает «голову» llama.cpp, раздаёт ей вопросы из очереди и пересобирает цепочку, когда кто-то ушёл. |
| `coordinator/social*.go` | Аккаунты, личные чаты, общий чат, проекты с кодами приглашения, события в прямом эфире (SSE). |
| `internal/rpctunnel` | Обратный туннель: участник сам подключается к серверу, а сервер через это соединение работает с его видеокартой. |
| `coordinator/` | Сервер. Регистрирует узлы, держит очередь задач и выдаёт их. При тайм-ауте выдаёт задачу заново. Часть задач считает на двух узлах и сверяет ответы: если ответы разошлись, третий узел решает спор, а узлы, которые часто ошибаются, отключаются. Здесь же веб-панель, API и автоматический HTTPS. |
| `client/` | Программа добровольца. Значок в трее, окно согласия, определение видеокарты, скачивание модели с проверкой SHA-256. Следит за паузами: простой компьютера, полноэкранная игра, батарея. Ограничивает нагрузку на видеокарту и видеопамять. Обновления только подписанные. |
| `internal/models` | Белый список моделей (Qwen3 0.6B / 1.7B / 4B / 8B) с хэшами. Он вшит в клиент: сервер может назвать только модель из списка, подсунуть свой файл он не может. |
| `web/` | Веб-панель Улья и страница загрузки (`download.html` можно вставить на сайт как есть). |
| `installer/` | Установщики: Windows (Inno Setup), Linux (.deb, .tar.gz), macOS (.dmg). |
| `deploy/` | Запуск координатора на сервере (systemd или Docker). |
| `tools/` | Генератор иконок и утилита подписи обновлений. |

## Безопасность и честность

- Пока человек не нажал «Согласен», клиент ничего не делает и даже не подключается к серверу.
- Клиент выполняет только один тип задач: генерацию текста моделью из белого списка. Он никогда не запускает код с сервера, и все параметры задачи перепроверяет сам.
- На сервер уходят только модель и объём памяти видеокарты, ОС и статус задач. Имя компьютера не отправляется.
- Связь только по HTTPS. Обычный http разрешён лишь для `127.0.0.1` при локальных тестах.
- Локальная панель настроек открывается только на этом компьютере (127.0.0.1) и защищена случайным ключом. Сторонние сайты обратиться к ней не могут.
- Обновление ставится, только если у него есть подпись Ed25519 с ключом Улья и совпадает контрольная сумма.

## Локальная сборка (аудитория, общежитие, клуб)

Весь сервер — одна программа. Её можно запустить на любом компьютере в локальной сети:

```bash
uley-coordinator -addr 0.0.0.0:8080 -signup-key КОД-ДЛЯ-СТУДЕНТОВ
```

На компьютерах участников в настройках программы указывается адрес `http://192.168.x.x:8080`. В локальной сети HTTPS не обязателен, в интернете — обязателен. Студенты открывают тот же адрес в браузере: чаты, проекты и табло работают так же, как в интернете. В локальной сети цепочка работает заметно быстрее, потому что задержки сети маленькие.

## Попробовать локально (без видеокарты)

Нужен Go 1.26+.

```bash
cd uley
go run ./coordinator/cmd/uley-coordinator -model qwen3-0.6b -require-api-key=false   # сервер на http://127.0.0.1:8080 (режим маленьких моделей)
go run ./client/cmd/uley -fake-engine                # клиент с эмулятором GPU, откроется окно согласия
# задача:
# (для локальной проверки запустите сервер с -require-api-key=false)
curl -X POST localhost:8080/api/v1/tasks -d '{"model":"qwen3-0.6b","prompt":"Привет!"}'
# или OpenAI-совместимо:
curl -X POST localhost:8080/v1/chat/completions -d '{"model":"qwen3-0.6b","messages":[{"role":"user","content":"Привет!"}]}'
```

Панель Улья: http://127.0.0.1:8080, страница загрузки: http://127.0.0.1:8080/download.

С настоящей моделью: скачайте `llama-server` из [релизов llama.cpp](https://github.com/ggml-org/llama.cpp/releases), укажите путь в `ULEY_LLAMA_SERVER=/путь/к/llama-server` и запустите клиент без `-fake-engine`.

Проверка большой модели целиком (нужны собранные `llama-server` и `ggml-rpc-server` из llama.cpp и маленькая GGUF-модель):

```bash
ULEY_LLAMA_BIN=~/llama.cpp/build/bin ULEY_TEST_MODEL=~/Qwen3-0.6B-Q8_0.gguf go test -run ChainEndToEnd -v ./client/agent/
```

Этот тест собирает цепочку из двух участников, получает ответ, «запускает игру» у одного из них, проверяет пересборку и получает ответ снова.

Тесты: `go test ./...`. Сквозной тест в `client/agent/agent_test.go` проверяет всю цепочку «координатор → узел → ответ», а также паузу при игре и повторную выдачу задачи.

## API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/v1/tasks` | `{"model","prompt"\|"messages","max_tokens","temperature"}` → задача |
| GET | `/api/v1/tasks/{id}?wait=30` | статус и ответ (ждёт до 60 с) |
| POST | `/v1/chat/completions` | OpenAI-совместимый синхронный вызов |
| GET | `/api/v1/stats`, `/api/v1/models` | статистика улья, список моделей |

Ключ API передаётся в заголовке `Authorization: Bearer КЛЮЧ` (ключи задаются в `-api-keys`).

## Улей как агент

В личных чатах и чатах проектов Улей работает как агент со своими инструментами (код инструментов — `coordinator/agent*.go`):
- **Память.** Сам запоминает важное о человеке (в проекте — о проекте, общее для группы). Всё видно и удаляется в «🧠 Что Улей помнит».
- **Навыки.** Сохранённые инструкции для повторяющихся задач («оформи отчёт по лабе»). В проекте они общие.
- **Поиск по прошлым разговорам.**
- **Задания по расписанию**: один раз, каждый день, раз в неделю, каждые N часов. Результат приходит в чат и в Telegram.
- **Telegram-бот**: `-telegram-token` (токен от @BotFather). Человек подключает аккаунт кодом из «📱 Telegram» на сайте.

Модель только выбирает инструмент, выполняет его код Улья на сервере. Добровольцы по-прежнему лишь считают модель. Часовой пояс заданий — `-tz` (по умолчанию Europe/Moscow).

## Hermes Agent и другие агенты

Улей отвечает как OpenAI-совместимый сервер (`/v1/chat/completions` с вызовом инструментов и потоковым ответом, `/v1/models`). Поэтому к нему можно подключить [Hermes Agent](https://github.com/NousResearch/hermes-agent) — открытый агент от Nous Research (лицензия MIT): память между сессиями, навыки, которые он создаёт себе сам, Telegram/Discord, планировщик задач. Агент работает на компьютере человека и сам выполняет свои инструменты. Добровольцы Улья только считают модель и никаких команд агента не получают.

Как подключить:
1. В веб-приложении Улья нажмите «🔑 API» и создайте ключ.
2. Выполните `hermes model`, выберите «Custom endpoint» и введите адрес `https://ваш-домен/v1`, ключ и модель (`qwen3-32b`). Или впишите в `~/.hermes/config.yaml`:
   ```yaml
   model:
     provider: custom
     base_url: https://ваш-домен/v1
     api_key: uley-…
     default: qwen3-32b
   ```

Hermes требует не меньше 64 000 токенов контекста. Поэтому Qwen3 32B в цепочке работает с расширенным контекстом (YaRN ×2) и сжатым кэшем (q8_0): 2 разговора по 64k. Цепочке нужно около 38 ГБ видеопамяти суммарно — примерно 7–8 игровых видеокарт.

Код Hermes в Улей не копировался, Улей лишь говорит на том же стандартном языке API. «Hermes» и «Nous Research» — чужие названия: Улей можно описывать как «совместим с Hermes Agent», но нельзя называть «Гермесом».

API закрыт без ключа (`-require-api-key`, по умолчанию включено). Для локальных тестов: `-require-api-key=false`.

## Релиз установщиков

1. Тег `uley-vX.Y.Z` (например `git tag uley-v0.1.0 && git push origin uley-v0.1.0`) запускает `.github/workflows/uley-release.yml`. Он собирает установщики и публикует GitHub Release. Ссылки вида `releases/latest/download/Uley-Setup-windows-x64.exe` всегда ведут на последнюю версию.
2. Перед первым настоящим релизом задайте в Settings → Secrets and variables → Actions:
   - переменную `ULEY_COORDINATOR_URL`: адрес координатора (`https://...`). Без неё клиент будет искать сервер на `127.0.0.1`;
   - переменную `ULEY_UPDATE_PUBLIC_KEY` и секрет `ULEY_UPDATE_PRIVATE_KEY`: выполните `go run ./tools/uley-sign keygen`;
   - секреты `WINDOWS_CERT_PFX_BASE64` и `WINDOWS_CERT_PASSWORD`, когда будет сертификат подписи кода.
3. Версия движка llama.cpp закреплена в `installer/llama-cpp-version.txt`.
